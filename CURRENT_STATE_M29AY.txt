M29BA ROOT CAUSE / FIX
- LTObjRef is polymorphic and derives from LTLink<HOBJECT>.
- On ARM/Vita the complete LTObjRef* begins at the vptr; the LTLink<HOBJECT> base subobject starts 4 bytes later.
- The old bridge used reinterpret_cast<CheapLTLink*>(pRef), causing the legacy list code to treat vptr/adjacent fields as prev/next pointers and corrupt memory.
- M29BA first static_casts LTObjRef* to the true LTLink<HOBJECT>* base subobject, then bridges that exact address to the legacy list layout.
- Object-reference deletion performs the reverse conversion before LTObjRef callbacks.
- Generated ARM object code confirms +4 bytes on insertion and -4 bytes on reverse conversion.
- No fake game-state transition is introduced.
