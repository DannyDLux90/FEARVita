M29BB ROOT CAUSE
- Original LithTech assumes client and server live in separate modules.
- FEARVita is monolithic, so both ILTClient and ILTServer holders exist simultaneously.
- Original LTObjRef::Link preferred ILTServer whenever present.
- Frontend camera/FX objects created by the Vita ILTClient are opaque VitaLocalObject handles, not LTObject instances.
- The server-first choice sent a VitaLocalObject into CLTServer::LinkObjRef, which cast it to LTObject*, read a bogus m_RefList, and crashed in legacy AddAfter.

M29BB FIX
- Vita LTObjRef::Link now asks ILTClient ownership first.
- Vita ILTClient LinkObjRef returns LT_OK only for handles in its VitaLocalObject registry.
- Unknown client handles return LT_NOTFOUND and fall through to ILTServer, so genuine server LTObject references still use real runtime reference-list tracking.
- First eight accepted local links are logged as: [objref] client-local-link accepted type=<type> count=<n>.
- Final ARM disassembly confirms client holder is called before server holder.
- No fake object/world/game-state transition is introduced.
