## FEAR SDK 1.08 compatibility

The public LithTech pin predates interfaces required by the retail F.E.A.R. ObjectDLL. M29AY restores those contracts against the public runtime, using the published F.E.A.R. SDK 1.08 (`xfw5/Fear-SDK-1.08` @ `2fc3557b0037d5fe01ac607b907d4b8511b9e4b2`) as reference instead of inventing gameplay behavior.

Implemented so far includes:
- retail command/class/property metadata adapters (`ICommandDef`, `ICommandMessageDef`, command/string-id properties and FEAR property flags);
- `LTOBB`, `LTSphere`, `IGameWorldPacker`, output-converter contracts and retail `_FINAL` assert macros;
- FEAR memory-category `ObjectBank<T, category>` compatibility;
- real `ILTServer::GetClientObject(HCLIENT)` backed by the existing server client/object relationship;
- server shadow-LOD adapters and global `SendSFXMessage(msg, flags)` broadcast form;
- FEAR-style `GenericProp` / `GenericPropList` accessors including string/bool/command/color/rotation;
- reference overloads for older pointer-based server APIs;
- `ObjectCreateStruct` physics group and child-model compatibility;
- C++17 fixes for old MSVC allocators, dependent-base lookup and invalid pointer `return false` sites;
- `LTIntersect::Point_Segment_DistSqr` and `LTIntersect::OBB_Point` with SDK semantics;
- `ILTModel::GetAnimKeyFrames` / `GetAnimNodeTransform` compatibility;
- uniform `ILTServer::SetObjectScale` mapped to the existing vector-scale runtime;
- `ILTServer::GetRealTimeMS` backed by Vita monotonic process time;
- `ILTMessage_Write::WriteHMODELANIM` and `ILTMessage_Read::ReadHMODELANIM` using the SDK `WriteType/ReadType` encoding;
- `TVector3::Clamp(min,max)` component-wise SDK behavior.

Important caveat: F.E.A.R. SDK 1.08 property type numbering differs from the older public runtime around FLAGS/BOOL/LONGINT/ROTATION/COMMAND/STRINGID. Compile compatibility is in place, but property decoding must be verified during real world instantiation before claiming gameplay correctness.

## ARM validation frontier

CMake configures successfully with `FEARVITA_MENU_LINK_ONLY=OFF` and all 533 retail server translation units.

A complete ARM/Vita clean compile reached the AI weapon block at approximately 374/533 before exposing the next SDK delta. Everything before it compiled, including AI.cpp, actions/goals, NavMesh generation, NavMesh links, nodes, path manager, sensors, sounds, squads, states and target-selection code.

The 374/533 failures were all central SDK conveniences rather than gameplay logic:
- `ILTServer::GetRealTimeMS`;
- `ILTMessage::{Write,Read}HMODELANIM`;
- `LTVector::Clamp`.

Those three contracts are now implemented from SDK 1.08 semantics. Because they modify widely included headers, Ninja intentionally restarted a full clean server recompile. This checkpoint therefore records **374/533 as the last proven frontier** and a new full validation pass in progress. There is not yet a completed ObjectDLL link and there is no M29AY VPK yet.

## Reproduce

```sh
export VITASDK=/path/to/vitasdk
export PATH="$VITASDK/bin:$PATH"

cmake -S project -B build-vita -G Ninja \
  -DFEARVITA_ENABLE_GAME_MODULES=ON \
  -DFEARVITA_MENU_LINK_ONLY=OFF \
  -DFEARVITA_LITHTECH_ROOT=/path/to/patched/lithtech \
  -DCMAKE_BUILD_TYPE=Release

ninja -C build-vita fearvita_fear_server_objects -j6
```
